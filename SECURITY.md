# Security and privacy — what is done, and what is still needed

**Short version for the owner:** PlagIQ v0.5 is suitable for a *supervised private pilot with non-confidential or synthetic documents*. It is **not yet approved for confidential, unpublished manuscripts.** Part B lists what must be in place first. None of Part B can be completed by code alone.

## A. Controls implemented in this repository (tested)

| Area | What PlagIQ does | Evidence |
|---|---|---|

| Manuscript never on disk (web app) | Uploads are held in memory (multipart spool raised above the 45 MB request cap). Before v0.5, files over 1 MB were spooled to a temporary file. | `test_uploads_are_kept_in_memory` |
| Manuscript kept only with its report, 24 hours | The stored report holds the summary (file name, SHA-256, counts, **source** excerpts) and the extracted manuscript text with the positions of its matches. The report is kept compressed in `plagiq-reports.sqlite3` on the website's private `/data` volume (`reports_store.py`) for `REPORT_HOURS` (default 24). Deleting a report or the account removes it at once. The AI detector's flagged passages and the integrity examples are never stored. Responses are `Cache-Control: no-store`. | Untrusted engine output | All engine fields are type-checked, bounded and rebuilt from an allowlist. The percentage is recomputed from merged spans and never taken from the engine. | `test_summary_sanitizes_untrusted_fields`, `test_summary_rejects_malformed` |
| Malicious source text | All titles, excerpts and file names are inserted as text (never HTML) in the browser and escaped in the PDF. The highlighted manuscript is server-escaped and contains only `<mark>` and `<br>` tags. | Unsafe URLs | Only `https://` source links are rendered, and they open with `noopener noreferrer`. PlagIQ never fetches user-supplied URLs. OpenAlex responses are capped at 5 MB. | code review |

## B. Required before confidential manuscripts (not done; needs infrastructure, policy or contracts)

1. **Accounts.** Telegram sign-in now gives each user an account and a check log. Still needed: an admin view, revocation and audit logs, and organisation accounts.
2. **Perimeter controls.** Add request-rate, body-size and concurrency limits at the edge (Railway or a CDN/WAF). The in-memory limit resets on restart and applies per replica.
3. **Parser isolation.** PDF/DOCX parsing runs in the web process. For untrusted uploads at scale, run extraction in a separate sandboxed worker with CPU/memory/time limits, and keep PyMuPDF patched.
4. **Malware scanning** of uploads if files are ever stored or forwarded. Today they are not stored.
5. **Encryption at rest and backups** for the engine volume: Railway volume encryption, an encrypted backup schedule and restore drills. The corpus contains licensed texts.
6. **Logging hygiene.** Disable request-body capture in any APM or error-tracking tool. Keep access logs short-lived. PlagIQ itself does not log manuscript content.
7. **Legal.** Data-processing agreements, a privacy notice, and a review against Uzbekistan's personal-data law (Law No. ZRU-547 and its data-localization requirements) by qualified counsel before public launch. OpenAlex's own retention cannot be revoked by deleting a PlagIQ report.
8. **Operations.** Separate staging and production, run one replica per service (state is in memory), have an incident-response contact, and document a deletion policy covering logs and backups.

## C. What PlagIQ does not claim

- PlagIQ itself computes no AI percentage. The optional AI detector shows **Pangram's** estimate (Russian and English), labelled as such, never as a verdict. The report lists checkable indicators (chatbot phrases, placeholders, hidden characters, look-alike letters, chat formatting, non-existent or mismatched DOIs). "No indicators found" does not mean human-written. See `evaluation/INTEGRITY.md`.
- No paraphrase or translation detection. Web search (optional, Yandex and/or Brave) covers only the top pages found for 3 short excerpts, not the whole web. Matching is exact seven-word overlap after normalization, including between Uzbek Latin and Cyrillic.
- Quotations and the bibliography are excluded only if the user chooses, using tested rules; the report shows both figures. The rules do not judge whether a citation is adequate.
- The PDF opens with a "Certificate of check" that certifies the check (document fingerprint, date, scope, result) and is verifiable by QR code. It is not an accredited certificate of originality or of the absence of plagiarism, and it says so on the page.
- Owner database tools: `/admin` library statistics and the source check (`/admin/diagnostic`) are owner-only (404 for everyone else) and reach the engine only over the private network with `ENGINE_API_KEY` (`/v1/inventory`, `/v1/diagnostic`, both 401 without it). They return counts and facts only, never source text: the check's sampled passage is not returned, and unpublished deposits are never shown.
- Sign-in: Telegram login (HMAC-verified), phone number through the bot (only the sender's own contact; single-use 10-minute link, stored server-side), or email + password (scrypt hash, 16-byte salt; 10 failures per email or connection per 15 minutes; addresses are not verified and nothing is emailed). Email accounts use negative user IDs and can never be owners. Plagiarism checks up to `ANON_MAX_WORDS` (1,000) words need no account; AI, archive and paid checks always do.
- Payments (Payme, Click, Uzum Bank) run in the providers' **test mode only**: the code refuses any `PAYMENTS_MODE` other than `test`, and Payme checkouts go to the sandbox. Callbacks are authenticated (Payme: HTTP Basic with the test key, compared in constant time; Click: MD5 `sign_string` with the secret key and the service ID; Uzum: HTTP Basic with the issued login and password, plus the service ID). Every state change runs in one SQLite `BEGIN IMMEDIATE` transaction; a top-up is credited once; a check's price is reserved before the check and refunded on failure. Deleting an account deletes its payment records and balance (refused while a payment is in progress). Card data never reaches PlagIQ. The callback paths skip only the optional pilot password, which the providers cannot send. Production payments require a separate review.

Report vulnerabilities privately to the repository owner; do not open a public issue with exploit details.
